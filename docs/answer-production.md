# 킹 받는 답변 제작 기록

2026-10-11. 단어 하나를 과하게 전달하는 장난 서비스다. 받는 사람은 답변을 모르는 상태로 선물을 받는다. 선물 상자를 누르면 포장이 흔들리고 고양이 다섯 마리가 등장한다. 드럼롤로 기대를 만든 다음 진지한 목소리로 “제 답변은”이라고 말한다. 다시 드럼롤을 넣어 일부러 답변을 늦춘다. 10초에 큰 답변과 고양이가 든 답변을 함께 공개하며 밝은 팡파르를 연주한다. 이후 군무와 음악을 반복하고 소리 끄기, 다시 보기, 정지를 제공한다.

## 직접 확인한 레퍼런스와 해석

사용자가 제공한 [dailybrrd의 October Cuadro 릴스](https://www.instagram.com/reel/DeHouwnujD0/)를 브라우저에서 확인했다. 흰 배경 위에 솜브레로와 콧수염을 쓴 여러 분홍색 새가 함께 움직이는 장면과 의료 장면을 직접 봤다. 확인한 영상은 1080×1920, 14.784초였다. 해당 영상은 고양이 영상이 아니다. 밝은 배경, 여러 캐릭터의 군무, 과장된 상황이라는 요소를 고양이 공연에 적용했다는 것은 제작자의 해석이다. 영상이나 음악 원본은 서비스에 복제하지 않았다.

## 실제 구현한 장면

| 시간 | 화면 | 오디오와 전달 |
| --- | --- | --- |
| 클릭 전 | 닫힌 선물 상자 | 사용자 클릭 전에는 소리를 재생하지 않는다. 답변을 가린다. |
| 0–1.8초 | 상자가 흔들리고 뚜껑이 날아간다 | 짧은 기대음. 선물을 열었다는 반응. |
| 1.8–5초 | 고양이 다섯 마리가 등장해 춤춘다 | 첫 드럼롤과 “두구두구두구두구”. |
| 5–7초 | “제 답변은…” | 한국어 합성 음성. 답변 공개를 약속한다. |
| 7–10초 | “두구두구두구” | 두 번째 드럼롤. 일부러 한 번 더 기다리게 한다. |
| 10초부터 | 큰 답변, 답변을 든 고양이, 색종이 | 직접 만든 분당 150박 팡파르와 “빰빠라밤”. 답변 공개. |
| 22.8초부터 | 고양이 군무 계속 | 6.4초 음악 루프. 정지 버튼으로 끝낸다. |

## 에셋과 재현

- 고양이: `imagegen`으로 생성한 실제 투명 배경의 3×2 스프라이트, `answer/assets/cat-dance.png`. 생성 결과 식별자 `exec-7607bc43-49e6-4d02-b999-14f82a61cf08`. 같은 오렌지 태비 고양이가 빈 팻말을 든 채 왼쪽 기울기·정면·오른쪽 기울기·왼발 들기·스쿼트·오른발 들기의 여섯 자세를 취하도록 요청했다. 이미지 생성 모델의 시드는 도구가 제공하지 않았다.
- 움직임: 브라우저에서 0.2초마다 자세를 바꾸고 고양이마다 위상을 엇갈린다. CSS 이동만으로 춤을 대체하지 않는다. `prefers-reduced-motion`에서는 정지 자세와 답변 공개만 제공한다.
- 음성: macOS `say`의 `Yuna`와 `Eddy (한국어(한국))`로 생성했다. 입력은 각각 “제 답변은”, “두구두구두구두구”, “빰빠라밤 빰빰 빠라밤”. 속도는 각각 145, 320, 250이다.
- 음악: `scripts/build-answer-audio.py`가 원래의 브라스 멜로디, 베이스, 킥, 스네어, 하이햇과 음성을 합성한다. FFmpeg `libmp3lame`, 128 kbps, 44.1 kHz, mono로 변환했다. 레퍼런스 곡은 사용하지 않았다.
- 글꼴: Pretendard Variable. 함께 배포한 `Pretendard-LICENSE.txt`를 따른다.

오디오 재현 예:

```sh
mkdir -p out/audio
say -v Yuna -r 145 -o out/audio/answer.aiff '제 답변은'
say -v 'Eddy (한국어(한국))' -r 320 -o out/audio/drum.aiff '두구두구두구두구'
say -v 'Eddy (한국어(한국))' -r 250 -o out/audio/fanfare.aiff '빰빠라밤 빰빰 빠라밤'
for name in answer drum fanfare; do
  ffmpeg -y -i "out/audio/$name.aiff" -ar 44100 -ac 1 "out/audio/$name.wav"
done
python3 scripts/build-answer-audio.py
for name in show dance; do
  ffmpeg -y -i "out/audio/$name.wav" -codec:a libmp3lame -b:a 128k "answer/assets/$name.mp3"
done
```

## 확인 범위

실제 Tailnet HTTPS 링크에서 단어 입력 → 링크 생성 → 받은 링크 열기 → 상자 클릭 → 답변 공개를 확인했다. 오디오 재생 상태, 다섯 팻말의 답변, 소리 끄기, 정지와 재시작을 확인했다. 데스크톱 및 390px 모바일 에뮬레이션에서 가로 넘침이 없었다. 합성 음원은 MP3 길이와 코덱 및 볼륨을 검사했다. 실제 iPhone·Android 하드웨어의 오디오 출력과 사용자의 미감 선택은 이 검증에 포함하지 않는다.

추가로 실제 클립보드 복사, 한글·이모지·기호의 링크 왕복, 24자 제한, 손상된 링크의 오류 안내, HTML 모양의 입력이 요소로 해석되지 않는 처리를 확인했다. 22.8초 뒤 6.4초 음악 루프로 넘어가며 재생이 이어졌다. 모션 줄이기 설정에서는 색종이와 자세 이동을 생략하고 답변이 공개됐다. HTML·CSS·JavaScript·고양이 이미지·음악의 Tailnet HTTPS 응답은 모두 200이었다.
